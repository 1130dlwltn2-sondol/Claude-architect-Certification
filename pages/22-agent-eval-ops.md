# 22. 에이전트 평가와 운영

에이전트를 만들었다면, 이제 "잘 돌아가는가"를 묻는 단계입니다. 시험의 D1에는 아키텍처뿐 아니라 신뢰성 있는 운영 관점도 포함됩니다.

## 평가 (Evals)

에이전트의 평가는 일반 소프트웨어 테스트와 다릅니다. 출력이 매번 조금씩 다르기 때문입니다. 그래서 평가는 보통 세 층위로 합니다.

단위 평가: 도구 하나하나가 제대로 동작하는지 확인합니다. 입력이 주어졌을 때 올바른 JSON Schema로 호출되는지, 에러를 잘 처리하는지 봅니다.

시나리오 평가: 대표적인 작업 시나리오를 정해놓고 끝까지 돌려봅니다. 성공 기준을 미리 정해야 합니다. "보고서가 생성되었다"가 아니라 "보고서에 매출, 비용, 이슈 세 섹션이 모두 포함되었다"처럼 구체적으로 정합니다.

LLM-as-judge: 평가 기준이 여러 갈래일 때, 별도의 LLM 호출로 각 측면을 평가합니다. 20장의 병렬화 패턴을 평가에 쓰는 셈입니다. 단, 평가자 모델의 편향을 의식해야 합니다.

평가의 황금률은 "복잡도를 올리기 전에 측정하라"입니다. 프롬프트를 고치든, 패턴을 바꾸든, 변경 전후의 점수를 비교할 수 있어야 합니다.

## 가드레일 (Guardrails)

가드레일은 에이전트가 해서는 안 될 일을 막는 장치입니다. 입력 단계와 출력 단계, 도구 실행 단계에 둘 수 있습니다.

입력 가드레일: 부적절한 요청을 걸러냅니다. 본 작업과 분리된 가벼운 모델로 검사하는 것이 효과적입니다. 같은 호출 안에서 검사와 본 처리를 다 하려 하면 둘 다 품질이 떨어집니다.

도구 가드레일: 위험한 도구 호출을 막습니다. 삭제나 결제 같은 되돌릴 수 없는 동작은 실행 전에 사람의 승인을 받게 합니다. 허용된 인자 범위를 벗어나면 차단합니다.

출력 가드레일: 최종 답변이 정책을 위반하지 않는지 확인합니다. 개인정보가 포함되었는지, 금지된 내용이 있는지 검사합니다.

## 휴먼인더루프 (Human-in-the-loop)

사람이 개입하는 지점을 설계하는 것이 중요합니다. 세 가지 방식이 있습니다.

체크포인트: 정해진 단계마다 사람이 확인합니다. 중요한 작업의 각 단계가 끝날 때마다 승인받는 방식입니다.

예외 시 개입: 평소에는 자율적으로 돌다가, 막히거나 위험한 상황에서만 사람에게 묻습니다. 운영 비용이 적게 듭니다.

사후 검토: 작업이 끝난 뒤 사람이 결과를 검토합니다. 위험도가 낮은 반복 작업에 적합합니다.

어느 방식을 쓸지는 작업의 위험도와 빈도로 결정합니다. 자주 반복되고 위험도가 낮으면 사후 검토, 드물지만 위험도가 높으면 체크포인트가 맞습니다.

## 정지 조건과 안전장치

에이전트 루프에는 반드시 정지 조건이 있어야 합니다.

- 최대 반복 횟수: 무한 루프 방지
- 시간 제한: 전체 작업의 데드라인
- 비용 상한: 토큰 사용량 기준 중단
- 연속 실패 임계값: 같은 실패가 N번 반복되면 중단하고 사람에게 알림

운영 환경에서는 여기에 로깅과 추적을 더합니다. 각 단계의 입력, 도구 호출, 결과를 기록해야 나중에 문제를 추적할 수 있습니다. Anthropic의 세 가지 원칙 중 "투명하게"가 운영 단계에서 빛을 발하는 지점입니다.

## 샌드박스 테스트

에이전트를 실제 환경에 풀기 전에는 격리된 환경에서 테스트합니다. 특히 다음을 확인합니다.

1. 도구가 실제 데이터를 건드리지 않는가 (읽기 전용 모드, 테스트 DB 사용)
2. 예상 밖의 도구 조합을 시도하지 않는가
3. 에러 상황에서 복구하는가, 아니면 같은 실패를 반복하는가
4. 정지 조건이 실제로 동작하는가

## 운영 체크리스트

- 평가 기준과 시나리오가 문서화되어 있는가
- 가드레일이 입력, 도구, 출력 단계에 각각 있는가
- 사람 개입 지점과 방식이 정해져 있는가
- 정지 조건 4종이 모두 설정되어 있는가
- 로깅으로 전 과정을 추적할 수 있는가
- 롤백 계획이 있는가

이 체크리스트는 시나리오형 문항에서 "이 설계의 문제점은?" 같은 질문에 그대로 쓸 수 있습니다.

## 실습: 내 에이전트의 실패 모드 찾기

21장 실습에서 설계한 주간 보고서 시스템을 다시 꺼냅니다. 다음 질문에 답해봅니다.

1. 이 시스템이 실패할 수 있는 경우를 5가지 적어보세요
2. 각 실패에 대해 탐지 방법과 대응을 한 줄씩 적어보세요
3. 사람에게 넘겨야 하는 경우 2가지를 정하세요

실패를 먼저 상상하는 습관이 좋은 아키텍트의 출발점입니다.

확인 문제

1. LLM-as-judge의 장점과 주의점을 설명해 보세요.
2. 입력 가드레일을 본 작업과 분리하는 이유를 설명해 보세요.
3. 휴먼인더루프의 세 가지 방식을 위험도와 빈도 관점에서 비교해 보세요.
4. 에이전트 루프에 필요한 정지 조건 4가지를 나열해 보세요.
