# 41. Claude Code 설정과 워크플로우

Claude Code의 진가는 설정에 있습니다. 프로젝트의 맥락을 미리 알려주고, 반복 작업을 명령어로 만들고, 특정 시점에 자동으로 끼어드는 장치를 두는 것입니다. 시험에서 D3의 핵심 출제 영역입니다.

## CLAUDE.md: 프로젝트의 설명서

프로젝트 루트에 CLAUDE.md 파일을 두면, Claude Code가 세션 시작 시 자동으로 읽습니다. 프로젝트의 개요, 기술 스택, 코딩 규칙, 주의사항을 적습니다.

```markdown
# 프로젝트 개요
온라인 서점의 주문 관리 API입니다.

# 기술 스택
- Python 3.12, FastAPI
- PostgreSQL, SQLAlchemy

# 코딩 규칙
- 함수에는 타입 힌트를 반드시 붙입니다
- 테스트는 pytest로 작성하고 tests/ 디렉토리에 둡니다
- DB 마이그레이션은 alembic으로만 수행합니다

# 주의사항
- production 브랜치에는 직접 푸시하지 마세요
- 결제 관련 코드는 수정 전에 반드시 설명을 먼저 하세요
```

좋은 CLAUDE.md의 조건:

- 짧고 구체적이다. 장황한 문서는 모델도 대충 읽는다
- 규칙은 "무엇을"이 아니라 "어떻게"로 적는다
- 예외와 금지 사항을 명시한다
- 프로젝트가 바뀌면 함께 업데이트한다

시험에서는 "CLAUDE.md에 무엇을 적어야 하는가"를 묻습니다. 정답은 프로젝트 특화 정보다. 일반적인 코딩 상식은 모델이 이미 안다.

## .claude 디렉토리

프로젝트의 .claude 디렉토리에는 Claude Code의 설정을 둡니다. 팀원 간에 공유되어 일관된 동작을 만듭니다.

- commands/: 커스텀 슬래시 커맨드 정의
- agents/: 서브에이전트 정의
- settings.json: 프로젝트 설정

버전 관리에 포함시켜 팀 전체가 같은 환경을 쓰게 하는 것이 권장됩니다.

## 슬래시 커맨드

자주 쓰는 지시를 명령어로 저장합니다. .claude/commands/ 디렉토리에 마크다운 파일로 정의합니다.

```markdown
# .claude/commands/review.md
다음 기준으로 코드를 리뷰해줘:
1. 보안 취약점 (SQL 인젝션, XSS 등)
2. 에러 처리 누락
3. 성능상 문제점
결과는 심각도 순으로 정리해줘.
```

이제 /review 라고 치면 이 지시가 실행됩니다. 팀의 리뷰 기준을 코드로 만든 셈입니다.

## 서브에이전트

특화된 작업을 맡는 하위 에이전트를 정의합니다. 21장의 coordinator-subagent 패턴이 여기서 구현됩니다.

예를 들어 "테스트 작성 전담", "문서화 전담" 서브에이전트를 만들어 두면, 메인 에이전트는 큰 그림에 집중하고 세부 작업은 위임합니다. 서브에이전트마다 별도의 컨텍스트를 쓰므로, 메인 세션의 컨텍스트가 오염되지 않습니다.

## Hooks: 자동 개입 지점

특정 이벤트가 발생했을 때 자동으로 실행되는 스크립트입니다. 예를 들어:

- 파일 수정 후: 자동으로 린터 실행
- 커밋 전: 테스트 실행
- 세션 시작 시: 프로젝트 상태 요약 출력

워크플로우 강제(21장)의 실제 구현입니다. "사람이 깜빡해도 시스템이 챙긴다"는 원칙을 코드로 박는 것입니다.

## MCP 연동

32장에서 만든 MCP 서버를 Claude Code에 연결하면, 코딩 세션에서 외부 도구를 쓸 수 있습니다.

```bash
claude mcp add weather-memo -- python /절대경로/weather_server.py
```

실무 예시: 사내 API 문서 MCP 서버를 연결해 두면, Claude Code가 API 스펙을 직접 조회하며 코드를 짭니다. DB 스키마 MCP 서버를 연결하면 마이그레이션 코드를 스키마에 맞춰 생성합니다. "에이전트에게 ground truth를 주는" 가장 실용적인 방법입니다.
