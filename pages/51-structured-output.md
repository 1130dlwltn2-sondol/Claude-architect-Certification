# 51. 구조화 출력과 고급 기법

프롬프트의 답을 코드가 받아 처리하려면, 출력이 예측 가능해야 합니다. 이 장에서는 구조화 출력과 고급 프롬프트 기법을 다룹니다.

## 왜 구조화 출력인가

에이전트 파이프라인에서 한 단계의 출력은 다음 단계의 입력입니다. 출력이 매번 형식이 다르면 파이프라인이 깨집니다. JSON 같은 구조화 출력은 기계가 읽을 수 있는 약속입니다.

방법은 두 가지입니다. 프롬프트로 형식을 지정하는 방법(50장)과, API의 구조화 출력 기능을 쓰는 방법입니다. 후자가 더 확실합니다.

## JSON Schema로 출력 강제하기

Anthropic API에서는 도구의 input_schema처럼 출력 스키마를 지정할 수 있습니다. 모델은 스키마에 맞는 JSON을 생성하도록 유도됩니다.

```python
response = client.messages.create(
    model="claude-sonnet-4-5-20250929",
    max_tokens=1024,
    messages=[{"role": "user", "content": "이 리뷰의 감정과 주제를 분석해줘: 배송이 너무 느려요"}],
    # 출력 형식을 강제하는 도구 정의 (실제 호출 없이 형식만 사용)
    tools=[{
        "name": "sentiment_result",
        "description": "감정 분석 결과를 담는 형식",
        "input_schema": {
            "type": "object",
            "properties": {
                "sentiment": {"type": "string", "enum": ["긍정", "부정", "중립"]},
                "topic": {"type": "string"},
                "confidence": {"type": "number"},
            },
            "required": ["sentiment", "topic", "confidence"],
        },
    }],
    tool_choice={"type": "tool", "name": "sentiment_result"},
)
```

tool_choice로 특정 도구를 강제하면, 모델은 반드시 그 형식으로 답합니다. 형식 준수가 필요한 파이프라인 단계에서 쓰는 기법입니다.

## 시스템 프롬프트 설계

시스템 프롬프트는 세션 전체에 적용되는 지시입니다. CLAUDE.md(41장)와 비슷한 역할을 API 수준에서 합니다.

좋은 시스템 프롬프트의 구조:

1. 역할과 목적: "당신은 고객 지원 분류기입니다"
2. 핵심 규칙: "반드시 지정된 형식으로만 답하세요"
3. 금지 사항: "추측하지 말고, 모르면 unknown이라고 답하세요"
4. 출력 형식: JSON Schema나 예시

시스템 프롬프트는 길어질수록 희석됩니다. 핵심만 남기고, 세부 지시는 각 사용자 메시지에 둡니다.

## 체이닝과 파이프라인

복잡한 작업은 여러 호출로 나눕니다. 20장의 프롬프트 체이닝 패턴입니다.

예: 문서 처리 파이프라인

1. 호출 1: 문서에서 핵심 주장 추출 (구조화 출력)
2. 코드: 주장의 출처 검증
3. 호출 2: 검증된 주장으로 요약 작성

각 단계의 출력 형식을 고정하면(구조화 출력), 단계 사이를 코드로 잇기 쉽습니다. 중간에 게이트(검증 코드)를 두면 품질이 올라갑니다.

## Temperature와 일관성

temperature는 출력의 무작위성을 조절합니다.

- 낮게(0~0.3): 분류, 추출, 형식 준수가 중요한 작업
- 중간(0.5~0.7): 일반적인 대화와 작성
- 높게(0.8~1.0): 아이디어 발상, 다양한 표현

시험 포인트: 구조화 출력이나 정확한 형식이 필요할 때는 temperature를 낮춥니다. "창의적인" 답이 필요한 평가에서는 temperature 설정 자체가 변수가 되므로 고정해야 합니다.

## 자기 일관성과 검증

중요한 판단에는 같은 질문을 여러 번 물어 다수결을 취하는 방법도 있습니다(20장의 투표 패턴). 비용은 늘지만 신뢰도가 올라갑니다.

또 다른 방법은 모델에게 자신의 답을 검증하게 하는 것입니다. "위 답을 다시 검토하고, 틀린 부분이 있으면 고쳐줘." 20장의 평가자-최적화 패턴의 1인 버전입니다.
